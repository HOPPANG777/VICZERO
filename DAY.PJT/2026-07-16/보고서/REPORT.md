```text

-> 검증된 TileLayout

-> CombatState가 unique_ptr<Map>으로 단독 소유
-> CombatSystem과 Renderer는 읽기 전용 참조
```

## 핵심 학습 결과

- 안전하게 조회할 수 있는 상태와 게임에서 유효한 상태는 다르다.
- 검증 전 데이터와 검증 완료 데이터를 타입으로 분리하면 잘못된 생성 경로를 줄일 수 있다.
- 구조 검증, 절차 생성 품질, 특정 전투 배치 가능성은 서로 다른 책임이다.
- 예상 가능한 무작위 후보 탈락과 구조적 계약 위반은 같은 재시도 정책을 사용하면 안 된다.
- 여러 시스템이 Map을 읽는다는 사실이 공동 소유를 의미하지는 않는다.
- `std::move`는 이동 자체가 아니라 자원 이전이 가능하다는 의도를 표현한다.
- 성공 상태와 `Map` 존재 여부가 어긋나는 결과는 타입 계약에서 허용하지 않아야 한다.
