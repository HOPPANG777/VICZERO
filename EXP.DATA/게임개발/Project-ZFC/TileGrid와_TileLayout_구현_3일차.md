## 오늘 한 일

검증되지 않은 원시 타일 데이터인 `TileGrid`를 `Map.h`에서 독립시키고, 구조 검증을 통과한 배치를 표현할 `TileLayout`을 실제 C++ 클래스로 구현했다. 외부에서 빈 객체나 원시 Grid로 직접 만들 수 없게 하고, `MapFactory`만 생성 권한을 가지도록 준비했다. 전체 복사는 막고 소유권 전달을 위한 이동은 허용했으며 외부 수정 기능은 제공하지 않았다.

## 핵심 문장

```text
TileGrid는 검증되지 않은 원시 타일 데이터다.
TileLayout은 구조 검증을 통과한 불변 타일 배치다.
MapFactory는 검증되지 않은 데이터가 TileLayout이 되는 것을 막는다.
검증 성공 여부는 상태 플래그가 아니라 TileLayout 타입 자체로 표현한다.
```

## 오늘 적용한 개념

### 유효한 클래스는 생성 경로까지 통제해야 한다

별도 클래스를 만드는 것만으로 잘못된 상태가 사라지지는 않는다. 외부 생성 제한, 검증 권한 집중, 생성 후 수정 차단이 함께 있어야 객체의 존재를 검증 성공의 증거로 사용할 수 있다.

### 전방 선언과 friendship

`TileLayout`은 아직 구현되지 않은 `MapFactory`를 소유하거나 호출하지 않는다. 타입 이름과 비공개 생성 접근 권한만 필요하므로 전체 헤더 대신 전방 선언과 friendship을 사용했다.

### 복사와 이동은 별도 정책이다

전체 2차원 데이터를 의도치 않게 복제하지 않도록 복사를 금지했다. 이후 `Map`의 값 멤버로 자원을 넘길 수 있도록 이동 생성과 이동 대입은 허용했다. 다만 생성 후 전체 배치 교체까지 금지할 것이라면 이동 대입은 다시 검토해야 한다.

### 최소 읽기 인터페이스

`TileLayout`은 크기, 범위, 타일 조회만 제공한다. 전체 `TileGrid`의 수정 가능한 참조와 Setter는 제공하지 않는다. 통행 가능 여부는 타일 배치가 아니라 `Map`의 게임 규칙이다.

### 확장성은 필요한 경계를 남기는 것이다

사용처가 하나뿐인 `MapValidator`를 미리 만들지 않았다. 현재는 `MapFactory` 안에서 검증과 생성을 구분하고, 실제 두 번째 사용처가 생기면 검증 로직을 추출한다.
