- 함수는 반환형, 함수 이름, 입력값, 함수 본문, 그리고 필요에 따라 `return`으로 이루어진다.

- 재귀함수는 자기 자신을 호출하는 함수이며, 반드시 탈출 조건이 필요하다.

## 5문장 핵심 설명

1. 함수는 복잡한 로직이나 한 본문에 너무 많은 기능이 들어가는 것을 막기 위해, 코드를 잘게 나누어 해결하는 방법이다.
2. 로직별로 코드를 나누면 코드의 재사용성과 가독성이 증가한다.
3. 함수는 반환형, 함수 이름, 입력값, 함수 본문, 그리고 `return`으로 이루어진다.
4. 함수를 호출하면 프로그램의 흐름이 함수로 이동하고, 함수 내부 로직이 실행된 뒤 필요한 경우 반환값을 돌려준다.
5. 결국 함수는 특정 역할을 맡은 독립적인 작업 단위라고 이해하면 된다.

## 함수가 필요한 이유

함수는 한 본문에 너무 많은 기능이 몰리는 것을 막기 위해 사용한다.

예를 들어 하나의 `main` 함수 안에 입력, 계산, 출력, 검증 같은 로직이 전부 들어가 있으면 코드가 길어지고 읽기 어려워진다. 이때 기능을 로직별로 나누면 같은 코드를 다시 사용할 수 있고, 코드를 읽는 사람도 흐름을 훨씬 쉽게 파악할 수 있다.

즉, 함수는 복잡한 문제를 작은 단위로 나누어 해결하고, 코드의 재사용성과 가독성을 높이는 문법이다.

## 함수의 기본 구조

```c
반환형 함수이름(매개변수목록)
{
    실행문;
    return 반환값;
}
```

- 반환형: 함수가 실행된 후 어떤 자료형의 데이터를 반환할 것인지 정의한다.
- 함수 이름: 이 함수가 호출되기 위해 붙이는 이름이다. 이름을 정할 때 이 함수가 어떤 기능을 하는지 참고해서 정해두면 나중에 편하다.
- 입력값: 함수의 로직에서 사용할 데이터를 받는 부분이다.
- 매개변수: 함수가 “이런 데이터를 받을 거예요” 하고 정의해두는 변수다.
- 함수 본문: 함수가 실제로 실행할 로직이 들어가는 부분이다.
- `return`: 반환값이 있는 경우에는 해당 값을 호출한 위치로 돌려준다. 반환값이 없는 경우에는 함수에서 벗어나겠다는 의미로 사용할 수 있다.

## 매개변수와 인자

매개변수와 인자는 비슷해 보이지만 위치가 다르다.

- 매개변수는 함수 정의부에서 “이 함수는 이런 데이터를 받을 거예요” 하고 선언하는 변수다.
- 인자는 실제로 함수를 사용할 때 괄호 안에 넣는 데이터다.

예를 들어 아래 코드에서 `num1`, `num2`는 매개변수이고, `5`, `9`는 인자다.

```c
int Add(int num1, int num2)
{
    return num1 + num2;
}

int result = Add(5, 9);
```

## 함수 호출 흐름

```text
호출하는 코드 -> 함수로 이동 -> 매개변수 전달 -> 함수 내부 실행 -> return -> 호출 위치로 복귀
```

함수를 호출하면 호출부에서 함수로 흐름이 이동한다. 함수는 전달받은 인자를 매개변수에 넣고, 본문 로직을 실행한다. 반환값이 있으면 호출부가 그 반환값으로 대체된다.

예를 들어 아래 코드는

```c
int result = Add(5, 9);
```

`Add(5, 9)`의 결과가 14라면, 결국 이렇게 이해할 수 있다.

```c
int result = 14;
```

## 함수의 네 가지 형태

입력값의 유무와 반환값의 유무에 따라 함수는 크게 네 가지 형태로 나눌 수 있다.

| 형태 | 의미 |
|---|---|
| 전달인자 있고, 반환값 있음 | 값을 받아서 처리한 뒤 결과를 돌려준다. |
| 전달인자 없고, 반환값 있음 | 외부 입력 없이 함수 내부 로직으로 결과를 만든다. |
| 전달인자 있고, 반환값 없음 | 값을 받아서 내부 로직만 실행한다. |
| 전달인자 없고, 반환값 없음 | 별도 입력 없이 내부 로직만 실행한다. |

전달인자와 반환값이 없는 함수는 이런 식이다.

```c
void WordPrint()
{
    printf("안녕하세요!\n");
}
```

이 함수는 호출되면 `안녕하세요!`를 출력할 뿐, 어떤 값을 반환하지는 않는다.

## void의 의미

`void`는 말 그대로 비어 있다는 뜻이다.

반환형 위치에 쓰이면 “이 함수는 아무런 값을 반환하지 않는다”는 의미다. 매개변수 위치에서 쓰이면 “이 함수는 전달인자를 받지 않는다”는 의미로 이해할 수 있다.

다만 `void`가 항상 “반환값도 없고 전달인자도 없다”는 뜻은 아니다. 어디에 쓰였는지에 따라 의미가 달라진다.

반환형에 `void`가 있으면 반환값을 주지 않아도 된다. 이때 `return 10;`처럼 값을 반환하면 안 된다. 다만 함수 실행을 중간에 끝내고 싶을 때 `return;`처럼 값 없이 사용하는 것은 가능하다.

매개변수 위치에 `void`가 있으면 해당 함수에 전달되는 입력값이 없다는 뜻이다. 즉, 괄호 안으로 값을 받지 않고 함수 안에 있는 로직만 실행한다는 의미다.

```c
void MyFunc(void)
{
    printf("Hello\n");
}
```

여기서는 반환값도 없고, 전달인자도 없는 함수다.

## return의 의미

`return`에는 두 가지 의미가 있다.

- 반환값이 있는 경우에는 해당 값을 호출한 위치로 전달한다.
- 반환값이 없는 경우에는 이 함수에서 벗어나겠다는 의미가 된다.

또한 한 함수 안에 `return`이 두 개 이상 있을 수도 있다. 이 경우 조건문을 통해 특정 조건을 만족하면 이 값을 반환하고, 다른 조건에서는 다른 값을 반환하는 식으로 사용할 수 있다.

## 함수 원형과 컴파일 진행 방향

함수의 원형을 선언할 때는 컴파일의 진행 방향을 주의해야 한다.

만약 함수의 선언이 진입점, 대표적으로 `int main()`보다 아래에 있다면 컴파일러는 `main` 안에서 호출한 함수가 어디에 선언되어 있는지 알지 못해서 에러를 낼 수 있다.

```c
int main()
{
    MyFunc();
    return 0;
}

void MyFunc()
{
    printf("히히");
}
```

이럴 때 전방 선언을 하면 문제가 해결된다. 먼저 함수의 원형을 선언해서 컴파일러에게 “이 함수 나중에 나오니까 서두르지 마”라고 힌트를 주는 것이다.

```c
void MyFunc();

int main()
{
    MyFunc();
    return 0;
}

void MyFunc()
{
    printf("히히");
}
```

## 지역변수

지역변수는 말 그대로 해당 변수가 선언된 범위 안에서만 사용할 수 있고, 그 범위를 벗어나면 사라지는 변수다.

범위를 판단하는 기준은 해당 변수가 선언된 중괄호다. 따라서 변수를 선언한 범위 밖에서 사용하면 에러가 발생할 수 있다. 이런 사소한 찐빠는 일으키지 않도록 주의해야 한다.

지역변수는 메모리 공간 중 스택이라는 곳에 저장된다. 스택은 후입선출 구조라서, 차곡차곡 쌓이고 가장 마지막에 저장된 데이터부터 차례대로 제거된다.

반복문이나 조건문 안에서도 지역변수를 선언할 수 있다. 예를 들어 `if`문 안에서 선언된 변수는 `if`문이 끝나면 사라진다. 그리고 같은 이름의 지역변수가 더 안쪽 범위에서 선언되면, 바깥쪽 지역변수를 가려버린다.

```c
int main()
{
    int num = 1;

    if (num == 1)
    {
        int num = 7;
        num += 10;
        printf("if 문 내에 지역 변수 num: %d\n", num);
    }

    printf("main 함수 내에 지역 변수 num: %d\n", num);
    return 0;
}
```

여기서 `if`문 안에 있는 `int num = 7;`을 주석 처리하면 출력값이 달라진다. 안쪽 지역변수가 바깥쪽 지역변수를 가리고 있었기 때문이다.

## 매개변수도 지역변수다

매개변수도 일종의 지역변수다. 함수에 값이 전달되면 그 함수 안에서만 사용되고, 함수가 끝나면 사라지기 때문이다.

따라서 매개변수는 지역변수다.

다만 반대는 성립하지 않는다. 모든 지역변수가 매개변수인 것은 아니다.

## 전역변수

전역변수는 말 그대로 전역에서 사용할 수 있는 변수다. 메모리 공간에 올라가면 프로그램이 끝날 때까지 지워지지 않는다.

처음 보면 좋은 것처럼 보이지만, 많이 쓰면 코드가 너무 복잡해질 수 있다. 어디서 값이 바뀌었는지 추적하기 어려워지기 때문이다.

전역변수를 너무 많이 쓰면 복잡해지는 이유는 함수와 변수의 연결 관계가 점점 꼬이기 때문이다. 예를 들어 A 함수와 B 함수가 같이 필요한 변수가 있어서 전역변수를 하나 만들고, 또 다른 두 함수가 같이 필요한 변수가 있어서 또 전역변수를 만드는 식으로 이어지면, 각 함수가 참조하는 전역변수가 너무 많아진다.

그러면 나중에 어떤 전역변수의 자료형이나 의미를 수정했을 때, 그 전역변수를 사용하는 함수들을 전부 확인해야 한다. 사진처럼 변수와 함수 사이에 선이 계속 얽히는 구조가 되는 것이다. 처음에는 편하려고 전역변수를 썼는데, 나중에는 하나를 고치면 어디까지 영향이 퍼지는지 알기 어려워진다.

그리고 전역변수와 같은 이름의 지역변수가 선언되면, 앞에서 본 것처럼 지역변수가 전역변수를 가려서 지역변수로 처리된다. 상황에 따라 에러가 날 수도 있으니 이름을 겹치게 짓는 것은 조심해야 한다.

이때 전역변수가 실제로 지워지는 것은 아니다. 컴파일러가 이름을 해석할 때 “이 이름과 더 가까운 범위에 선언된 지역변수가 있구나”라고 판단해서, 같은 이름의 전역변수보다 지역변수를 우선해서 사용하는 것이다. 즉, 가까운 선언이 바깥쪽 선언을 가리는 구조다.

## static 변수

`static` 변수는 선언된 범위 안에서만 사용할 수 있지만, 메모리 공간에는 프로그램이 종료될 때까지 계속 올라가 있는 변수다.

즉, 전역변수처럼 오래 살아남는 장점은 어느 정도 가져오면서도, 사용할 수 있는 범위는 제한해서 전역변수의 단점을 줄이는 방법이라고 볼 수 있다.

일반 지역변수와의 차이는 생존 기간이다. 일반 지역변수는 해당 함수가 종료되면 지워지지만, `static` 지역변수는 함수가 종료되어도 지워지지 않고 프로그램이 종료될 때까지 남아 있다. 그래서 다음에 같은 함수가 다시 호출되었을 때도 이전 값을 계속 사용할 수 있다.

## register 변수

`register` 변수는 컴파일러에게 “이 변수 자주 쓰니까 CPU 안에 있는 빠른 레지스터 메모리 공간에 올려줘”라고 힌트를 주는 방법이다.

다만 `register`를 쓴다고 해서 반드시 레지스터에 올라간다는 의미는 아니다. 레지스터는 빠르고 중요한 공간이라 아무 변수나 올릴 수 없고, 컴파일러가 판단해서 결정한다.

그래서 이걸 남발해도 큰 의미는 없다.

처음에는 이 부분이 헷갈렸다. 나는 분명히 CPU 안의 레지스터는 가장 중요하고 제한된 메모리 자원이라서, 프로그래머가 직접적으로 컨트롤할 수 없다고 알고 있었다. 그런데 책에서 `register` 변수를 보고 “그럼 프로그래머가 레지스터를 직접 지정할 수 있다는 건가?” 싶었다.

정리하면, `register`는 레지스터를 직접 컨트롤하는 문법이 아니다. 컴파일러에게 “이 변수는 자주 쓰이니까 가능하면 빠른 레지스터에 올려줘”라고 힌트를 주는 문법이다. 실제로 레지스터에 올라갈지 말지는 컴파일러가 결정한다.

## 재귀함수

재귀함수는 자기 자신을 호출하는 함수다.

자기 자신을 계속 호출하기 때문에 확실한 탈출 조건이 없다면 스택 오버플로우로 이어지기 쉽다. 재귀함수가 계속 자기 자신을 호출할 수 있는 이유는, 함수가 호출될 때마다 새로운 함수 호출 정보가 메모리 공간에 쌓이기 때문이다.

따라서 재귀함수에는 반드시 탈출 조건이 필요하다. 재귀함수는 자기 호출을 계속 반복하는 함수이기 때문에, 탈출 조건이 없다면 컴퓨터의 메모리를 다 먹을 때까지 계속해서 호출을 진행하게 된다. 결국 호출 정보가 스택에 계속 쌓이고, 더 이상 쌓을 수 없는 순간 스택 오버플로우가 발생한다.

재귀함수를 사용하는 이유는 어떤 반복 구조를 더 짧고 깔끔하게 표현할 수 있기 때문이다. 대표적인 예시는 팩토리얼 함수다.

다만 나는 아직 재귀함수가 항상 더 좋다고 느껴지지는 않는다. 오히려 `for`문으로 짜는 편이 더 안전하고 가독성도 크게 떨어지지 않는 것처럼 보인다. 특히 게임처럼 대량의 데이터를 처리하는 상황에서는 함수 호출 오버헤드가 많이 쌓일 수 있으므로, 재귀함수를 무조건 쓰기보다는 반복문과 비교해서 판단해야 한다고 생각한다.

그래도 재귀함수가 더 유리해지는 구조가 있다. 다음에 가야 할 길이 여러 갈래로 갈라지고, 갔다가 다시 돌아와야 하는 구조에서는 재귀가 흐름을 더 자연스럽게 표현할 수 있다. 예를 들면 트리, 그래프, 탐색 같은 구조다.

이런 경우에는 “현재 위치에서 할 일을 하고 -> 다음 갈래로 들어가고 -> 끝나면 다시 돌아온다”는 흐름이 재귀 호출과 잘 맞는다. 그래서 단순 반복은 `for`문이 더 편할 수 있지만, 갈림길을 따라 깊이 들어갔다가 되돌아오는 문제에서는 재귀가 더 유리할 수 있다.

## 예제 흐름 정리

- 예제: `Add(5, 9)` 형태의 덧셈 함수
- 입력: `5`, `9`
- 호출되는 함수: `Add`
- 함수 내부 처리: 전달받은 두 값을 매개변수로 받아 더한다.
- 반환 또는 출력: 더한 결과인 `14`를 반환한다.
- 이 예제가 보여주는 핵심: 함수 호출부는 함수 내부 로직이 끝난 뒤 반환값으로 대체될 수 있다.

## Codex 평가 요청용 메모

정리를 평가받을 때는 아래 기준으로 확인한다.

- 개념 정확도: 90/100
- 빠진 핵심: 함수 원형에서 매개변수 이름은 생략 가능하다는 점, 지역변수/전역변수/static 변수의 저장 영역 차이를 더 자세히 정리하면 좋다.
- 예제 이해도: 함수 호출부가 반환값으로 대체되는 흐름을 잘 잡았다.
- 헷갈릴 표현: `void`는 위치에 따라 의미가 달라진다는 점을 계속 의식하면 된다.
- 보완할 자가문제: 함수 원형, static 지역변수, 재귀함수 탈출 조건을 코드로 직접 써보는 문제를 추가하면 좋다.

## 적용 아이디어

- 함수는 로직을 나눌 때만 쓰는 것이 아니라, “이 코드가 어떤 역할을 하는지 이름으로 설명하는 도구”로도 쓸 수 있다.
- 앞으로 C 코드를 짤 때 한 함수 안에 너무 많은 일을 넣지 말고, 역할이 달라지는 지점에서 함수를 나눠보자.
