## 가장 먼저 기억할 것

자료구조 공부의 목적은 구조 이름과 코드를 많이 외우는 것이 아니다.

문제에서 자주 하는 일이 무엇인지 파악한 뒤, 그 일을 빠르고 안전하게 할 수 있는 데이터 배치 방식을 고르는 것이 목적이다. 따라서 매 주제는 아래 순서로 배운다.

```text
문제 상황 -> 필요한 연산 -> 데이터 배치 방법 -> 연산 과정 -> 비용 -> C++ 표현 -> 다른 사람에게 설명
```

## 매일 사용하는 다섯 가지 질문

새로운 자료구조를 만나면 아래 질문에 답한다.

1. 무엇을 어떤 모양과 규칙으로 저장하는가?
2. 어떤 연산을 제공하는가?
3. 각 연산을 하면 데이터가 실제로 어떻게 움직이는가?
4. 빠른 연산과 느린 연산은 무엇이며 왜 그런가?
5. 어떤 문제에서 선택하고, 어떤 문제에서는 피해야 하는가?

## C++ 학습 범위

이 과정은 C++ 전체를 배우는 과정은 아니다. 자료구조를 이해하는 데 필요한 문법만 그때그때 사용한다.

- 값과 자료형: `int`, `bool`, `string`
- 흐름 제어: `if`, `for`, `while`
- 함수와 매개변수
- 배열과 `std::vector`
- `struct`, `class`, 생성자
- 포인터, 참조, `nullptr`
- 템플릿 표기 읽기: `vector<int>`, `stack<string>`
- STL 컨테이너와 반복자 범위 기반 반복문

문법 때문에 자료구조 설명이 막히면 문법을 10분 보충하고 본 주제로 돌아온다.

## 정확하게 가르치는 설명의 4단계

쉬운 비유만 말하면 친절하지만 부정확해질 수 있고, 전문 용어만 말하면 정확하지만 이해시키기 어렵다. 항상 네 단계로 설명한다.

1. 상황: 어떤 불편을 해결하려는지 말한다.
2. 비유: 일상 예로 모양과 규칙을 보여준다.
3. 정확한 정의: 비유가 놓친 부분을 전문 용어로 바로잡는다.
4. 예외와 선택: 언제 유리하고 언제 불리한지 말한다.

예를 들어 스택을 이렇게 설명한다.

> 접시를 위에 쌓으면 마지막에 올린 접시를 먼저 꺼냅니다. 스택도 한쪽 끝에서만 데이터를 넣고 빼는 LIFO 추상 자료형입니다. 다만 실제 컴퓨터 안에 접시가 있는 것은 아니고, 배열이나 연결 리스트로 이 규칙을 구현합니다. 중간 항목을 자주 꺼내야 한다면 스택은 맞지 않습니다.

## 자주 생기는 오개념

- 자료구조와 C++ 컨테이너는 같은 말이 아니다. `stack`은 규칙이고 `std::stack`은 그 규칙을 제공하는 C++ 도구다.
- Big-O는 실제 실행 시간을 초 단위로 말하는 것이 아니다. 입력 크기가 커질 때 일의 증가 모양을 나타낸다.
- 연결 리스트는 모든 삽입이 무조건 O(1)이 아니다. 삽입 위치를 찾는 시간이 필요할 수 있다.
- 이진 탐색은 데이터가 정렬되어 있어야 한다.
- 해시 테이블의 O(1)은 보통 평균 시간이며 충돌과 재해싱 비용이 있다.
- 이진 트리와 이진 탐색 트리는 다르다. 탐색 트리에는 값의 순서 규칙이 추가된다.
- 힙은 모든 값이 정렬된 구조가 아니다. 부모와 자식 사이의 우선순위 규칙만 보장한다.
- 그래프 탐색에서는 방문 표시가 없으면 같은 정점을 반복 방문할 수 있다.
