## 0. 시작 질문

지금은 틀려도 괜찮다. 공부하기 전에 아래 질문에 한두 문장으로 답한다.

- 게임의 아이템 100개를 저장한다면 어떤 모양으로 보관하고 싶은가?
- 가장 최근에 먹은 아이템을 먼저 취소해야 한다면 어떤 규칙이 필요할까?
- 이름으로 학생을 빨리 찾고 싶다면 단순히 학생들을 아무렇게나 모아 두어도 될까?

오늘 수업이 끝난 뒤 같은 질문에 다시 답하면 생각이 얼마나 구체적으로 바뀌었는지 확인할 수 있다.

## 1. 자료란 무엇인가

자료, 즉 데이터는 컴퓨터가 저장하고 처리할 수 있게 표현한 값이다.

예를 들어 학생 한 명을 표현하는 다음 값은 모두 자료다.

- 이름: 민수
- 나이: 17
- 점수: 85
- 합격 여부: 참

C++에서는 이런 값을 각각 변수에 담을 수 있다.

```cpp
string name = "민수";
int age = 17;
int score = 85;
bool passed = true;
```

그런데 실제 문제에는 값 하나만 있는 경우보다 값이 아주 많이 있는 경우가 많다. 학생 1,000명의 점수, 게임 아이템 500개, 지도 위의 장소 10,000개처럼 말이다.

값이 많아지면 “무엇을 저장할까?”만큼 “어떻게 배치하고 어떤 규칙으로 다룰까?”가 중요해진다.

## 2. 자료구조란 무엇인가

자료구조는 여러 데이터를 목적에 맞게 저장하고 사용할 수 있도록 정한 배치 방식과 연산 규칙이다.

더 쉽게 나누면 두 가지가 들어 있다.

1. 모양: 데이터들이 서로 어떤 관계로 놓이는가?
2. 규칙: 데이터를 어떻게 넣고, 빼고, 찾고, 읽는가?

### 책장 비유

책 100권이 바닥에 아무렇게나 흩어져 있어도 책 100권이라는 데이터는 존재한다. 하지만 원하는 책을 찾기 어렵다.

책을 책장 칸마다 번호순으로 꽂으면 다음과 같은 구조가 생긴다.

- 책이 놓이는 위치가 있다.
- 순서를 정하는 규칙이 있다.
- 번호를 이용해 특정 위치의 책을 찾을 수 있다.
- 중간에 새 책을 넣으려면 다른 책을 옮겨야 할 수 있다.

이 비유에서 중요한 점은 정리하면 모든 일이 무조건 빨라지는 것이 아니라는 것이다. 특정 책을 찾기는 쉬워졌지만, 번호순을 유지하며 중간에 책을 넣는 일은 번거로워졌다.

자료구조도 마찬가지다. 어떤 일을 빠르게 만들면 다른 일이 느려지거나 메모리를 더 사용할 수 있다.

### 정확한 정의로 다시 말하기

책장 비유는 이해를 돕지만 컴퓨터의 실제 자료구조 정의를 대신하지는 않는다.

> 자료구조는 데이터를 저장하는 방식, 데이터 사이의 관계, 그리고 그 데이터를 조작하는 연산을 함께 정의한 것이다.

“자료구조는 데이터를 담는 상자다”라고만 말하면 부족하다. 상자의 내부 배치와 사용할 수 있는 연산이 빠져 있기 때문이다.

## 3. 왜 자료구조가 여러 종류인가

모든 상황에서 가장 좋은 자료구조는 없다. 문제마다 자주 하는 일이 다르기 때문이다.

| 문제 상황 | 자주 필요한 일 | 어울릴 가능성이 큰 구조 |
|---|---|---|
| 번호로 학생 점수 읽기 | 몇 번째 값에 바로 접근 | 배열, vector |
| 실행 취소 | 가장 최근 작업부터 꺼내기 | 스택 |
| 매표소 대기 | 먼저 온 사람부터 처리 | 큐 |
| 아이디로 회원 찾기 | 키로 빠르게 검색 | 해시 테이블 |
| 폴더 구조 표현 | 부모와 자식 관계 | 트리 |
| 지하철 노선 표현 | 여러 장소 사이의 연결 | 그래프 |

자료구조를 고를 때 “데이터가 몇 개인가?”만 묻지 않는다. 다음 질문이 더 중요하다.

- 특정 위치를 자주 읽는가?
- 값을 자주 찾는가?
- 중간 삽입과 삭제가 자주 일어나는가?
- 들어온 순서나 우선순위를 지켜야 하는가?
- 데이터 사이에 계층이나 연결 관계가 있는가?

## 4. 자료구조와 알고리즘의 차이

자료구조와 알고리즘은 함께 나오지만 같은 것은 아니다.

- 자료구조: 데이터를 어떤 모양과 규칙으로 보관할지 정한다.
- 알고리즘: 문제를 해결하기 위해 어떤 순서로 행동할지 정한다.

요리로 비유하면 다음과 같다.

- 냉장고 칸과 양념통 정리 방식은 자료구조에 가깝다.
- 재료를 씻고, 썰고, 볶는 순서는 알고리즘에 가깝다.

그러나 둘은 서로 영향을 준다. 재료가 어디에 있는지 찾기 어렵다면 요리 순서가 좋아도 전체 시간이 오래 걸린다. 반대로 재료 정리가 잘되어 있어도 잘못된 조리 순서를 쓰면 음식이 완성되지 않는다.

컴퓨터에서도 이진 탐색이라는 알고리즘은 데이터가 정렬된 배열 같은 형태로 준비되어 있을 때 힘을 발휘한다. 적절한 자료구조와 알고리즘을 함께 선택해야 한다.

## 5. ADT란 무엇인가

ADT는 Abstract Data Type의 약자이며 한국어로 추상 자료형이라고 한다.

처음에는 이름이 어렵지만, 핵심은 “사용 규칙”과 “내부 제작 방법”을 분리하는 것이다.

### 자판기 비유

자판기를 사용하는 사람은 다음만 알면 된다.

- 돈을 넣는다.
- 상품 번호를 누른다.
- 상품과 거스름돈을 받는다.

사용자는 자판기 안에서 모터가 어떻게 돌고 상품이 어떤 레일로 떨어지는지 몰라도 된다. 버튼과 결과라는 약속을 알면 사용할 수 있다.

ADT도 외부에서 사용할 수 있는 값과 연산, 그리고 지켜야 할 규칙을 정의한다. 실제로 내부를 배열로 만들지 연결 리스트로 만들지는 구현의 문제다.

### 스택 예시

스택 ADT는 보통 다음 규칙을 가진다.

- `push`: 맨 위에 데이터를 넣는다.
- `pop`: 맨 위 데이터를 제거한다.
- `top`: 맨 위 데이터를 확인한다.
- 마지막에 넣은 데이터를 가장 먼저 꺼낸다. 이를 LIFO라고 한다.

이 스택은 배열로 구현할 수도 있고 연결 리스트로 구현할 수도 있다.

```text
스택이라는 사용 규칙(ADT)
       ├─ 배열을 이용한 구현
       └─ 연결 리스트를 이용한 구현
```

따라서 다음 두 문장을 구분해야 한다.

- 스택은 마지막에 넣은 것을 먼저 꺼내는 추상 자료형이다.
- `std::stack`은 C++에서 스택 규칙을 사용할 수 있게 제공하는 표준 라이브러리 도구다.

## 6. 자료구조에서 자주 보는 다섯 연산

### 접근 access

특정 위치의 값을 바로 읽거나 바꾸는 일이다.

```cpp
scores[2]
```

위 코드는 `scores`의 세 번째 위치에 접근한다. C++ 인덱스는 0부터 시작하므로 인덱스 2는 세 번째다.

### 탐색 search

원하는 값이 어디에 있는지 알아내는 일이다.

```text
[70, 85, 90, 60]에서 90은 어디에 있는가?
```

접근은 위치를 이미 알고 있고, 탐색은 원하는 값의 위치를 찾는다는 차이가 있다.

### 삽입 insert

새 데이터를 구조 안에 추가하는 일이다. 어느 위치에 넣는지에 따라 비용이 달라질 수 있다.

### 삭제 remove 또는 erase

기존 데이터를 구조에서 없애는 일이다. 삭제 뒤에도 구조의 규칙을 유지해야 한다.

### 순회 traversal

저장된 데이터를 정해진 방식으로 하나씩 방문하는 일이다. 모든 학생 점수를 출력하거나 합계를 구하는 일이 예다.

## 7. 배열로 첫 구조 보기

다섯 명의 점수를 저장해 보자.

```cpp
int scores[5] = {70, 85, 90, 60, 100};
```

메모리의 정확한 주소는 실행할 때 정해지지만, 개념적으로는 값이 연속된 칸에 놓인다고 볼 수 있다.

```text
인덱스:   0    1    2    3     4
값:      70   85   90   60   100
```

`scores[3]`을 읽으면 네 번째 값인 60을 얻는다. 배열은 각 원소의 위치를 계산할 수 있기 때문에 인덱스로 빠르게 접근한다.

하지만 인덱스 2 위치에 88을 새로 넣고 기존 값을 모두 보존하려면 어떻게 될까?

```text
삽입 전: 70  85  90  60  100
                 ↑ 여기에 88

이동 후: 70  85  88  90  60  100
```

뒤의 값들을 한 칸씩 옮겨야 한다. 빠른 위치 접근을 얻는 대신, 중간 삽입에는 이동 작업이 생긴다.

이것이 자료구조의 장단점을 보는 기본 방식이다.

## 8. C++ `vector` 맛보기

고정 크기 배열보다 크기를 유연하게 다룰 때 C++에서는 `std::vector`를 자주 사용한다.

```cpp
#include <iostream>
#include <vector>

int main()
{
    std::vector<int> scores = {70, 85, 90};

    scores.push_back(60);

    std::cout << scores[1] << '\n';

    for (int score : scores)
    {
        std::cout << score << ' ';
    }

    return 0;
}
```

### 줄별 의미

- `#include <vector>`: 표준 라이브러리의 `vector`를 사용하겠다고 알린다.
- `std::vector<int>`: `int` 값을 여러 개 저장하는 vector 타입이다.
- `scores = {70, 85, 90}`: 처음 세 값을 넣어 만든다.
- `push_back(60)`: 맨 뒤에 60을 추가한다.
- `scores[1]`: 인덱스 1, 즉 두 번째 값 85에 접근한다.
- `for (int score : scores)`: 처음부터 끝까지 모든 값을 하나씩 순회한다.

### 손으로 상태 추적하기

| 실행 직후 | `scores`의 논리적 내용 |
|---|---|
| 처음 생성 | `[70, 85, 90]` |
| `push_back(60)` 후 | `[70, 85, 90, 60]` |
| `scores[1]` 출력 | 내용은 그대로, `85` 출력 |
| 반복문 | `70 85 90 60` 순서로 방문 |

`vector`가 커질 때 내부 메모리에서 어떤 일이 생기는지는 5일차에 자세히 배운다. 오늘은 “같은 종류의 값을 순서대로 저장하고, 인덱스로 접근하며, 뒤에 값을 추가할 수 있다”까지만 정확히 잡는다.

## 9. 구조를 고르는 사고 연습

다음 상황에서 먼저 “자주 필요한 연산”을 적고, 그다음 어울리는 구조를 예상한다. 아직 구조를 배우지 않았으므로 예상이 틀려도 된다.

### 상황 A — 게임의 되돌리기

가장 최근 행동부터 취소해야 한다.

- 자주 필요한 연산: 최근 행동 추가, 가장 최근 행동 확인·삭제
- 중요한 순서 규칙: 마지막에 들어온 것이 먼저 나감
- 예상 구조: 스택

### 상황 B — 프린터 대기열

먼저 요청된 문서를 먼저 출력해야 한다.

- 자주 필요한 연산: 뒤에 요청 추가, 앞의 요청 처리
- 중요한 순서 규칙: 먼저 들어온 것이 먼저 나감
- 예상 구조: 큐

### 상황 C — 학생 번호로 점수 조회

학생 번호가 주어졌을 때 점수를 자주 읽는다.

- 자주 필요한 연산: 번호를 이용한 접근 또는 검색
- 중요한 조건: 번호 범위가 연속적인가, 중간 번호가 많이 비는가?
- 예상 구조: 번호가 작고 연속적이면 배열/vector, 번호가 듬성듬성하거나 문자열이면 해시 맵도 고려

마지막 예처럼 정답이 하나로 고정되지 않을 수 있다. 문제의 조건이 바뀌면 선택도 달라진다.

## 10. 오늘 반드시 구분할 문장

| 헷갈리는 쌍 | 정확한 구분 |
|---|---|
| 데이터 / 자료구조 | 데이터는 값이고, 자료구조는 여러 값을 배치하고 다루는 방식과 규칙이다. |
| 자료구조 / 알고리즘 | 자료구조는 보관 방식, 알고리즘은 문제 해결 절차다. |
| 접근 / 탐색 | 접근은 위치를 알고 값을 가져오며, 탐색은 원하는 값의 위치를 찾는다. |
| ADT / 구현 | ADT는 외부 규칙, 구현은 그 규칙을 실제로 만드는 내부 방법이다. |
| 스택 / `std::stack` | 스택은 LIFO 규칙의 ADT, `std::stack`은 C++ 표준 도구다. |

## 11. 확인 문제

답을 보기 전에 종이나 별도 메모에 먼저 푼다.

1. 자료구조를 “여러 데이터를 담는 상자”라고만 설명하면 어떤 내용이 빠지는가?
2. 배열에서 위치를 아는 값 읽기와, 값 90의 위치 찾기는 각각 어떤 연산인가?
3. 스택을 배열과 연결 리스트로 모두 만들 수 있다는 사실은 ADT와 구현의 어떤 차이를 보여주는가?
4. 프린터 요청을 먼저 들어온 순서대로 처리하려면 어떤 규칙의 구조가 필요한가?
5. 자료구조를 고르기 전에 문제에서 가장 먼저 찾아야 하는 것은 무엇인가?

### 정답과 해설

1. 데이터의 배치 방식, 데이터 사이의 관계, 삽입·삭제·탐색 같은 연산 규칙이 빠진다.
2. 위치를 아는 값 읽기는 접근, 90의 위치를 알아내는 것은 탐색이다.
3. 외부에서 지켜야 할 스택의 LIFO 규칙은 같아도 내부 제작 방법은 여러 가지일 수 있음을 보여준다.
4. 먼저 들어온 것이 먼저 나오는 FIFO 규칙의 큐가 어울린다.
5. 자주 필요한 연산과 반드시 지켜야 하는 순서·관계 조건을 먼저 찾아야 한다.

## 12. 3분 가르치기 대본

아래를 그대로 외우지 말고, 흐름만 보고 자신의 말로 설명한다.

### 1단계 — 문제 제시

“책 100권이 바닥에 흩어져 있으면 원하는 책을 찾기 어렵습니다. 컴퓨터에서도 값이 많아지면 어떻게 정리할지가 중요합니다.”

### 2단계 — 쉬운 정의

“자료구조는 여러 데이터를 목적에 맞게 배치하고, 넣기·빼기·찾기 같은 사용 규칙을 정한 것입니다.”

### 3단계 — 종류가 많은 이유

“모든 일에 최고인 구조는 없습니다. 배열은 번호로 접근하기 좋지만 중간 삽입 때 값을 옮길 수 있습니다. 스택은 최근 작업 취소에 좋고 큐는 먼저 온 요청 처리에 좋습니다.”

### 4단계 — 정확한 구분

“자료구조는 데이터의 보관 방식이고 알고리즘은 문제 해결 절차입니다. ADT는 스택처럼 외부에서 보이는 연산과 규칙을 말하고, 배열이나 연결 리스트는 그 규칙을 만드는 구현 방법이 될 수 있습니다.”

### 5단계 — 마무리

“그래서 자료구조를 선택할 때는 이름을 먼저 고르는 것이 아니라, 문제에서 자주 필요한 연산이 무엇인지 먼저 찾아야 합니다.”

## 13. 상대가 물어볼 수 있는 질문

### 그냥 vector 하나만 계속 쓰면 안 되나요?

작은 프로그램에서는 가능할 때도 있다. 하지만 데이터가 커지거나 특정 연산이 매우 자주 일어나면 불필요하게 느려지거나 코드가 복잡해질 수 있다. 또한 부모-자식 관계나 연결망처럼 vector 하나만으로 의미를 자연스럽게 표현하기 어려운 문제도 있다.

### 자료구조가 알고리즘보다 먼저인가요?

항상 한쪽이 먼저라고 정할 수는 없다. 문제를 해결할 절차를 생각하면서 필요한 자료구조가 드러나기도 하고, 사용할 수 있는 자료구조에 따라 알고리즘이 달라지기도 한다. 둘은 함께 설계한다.

### ADT도 자료구조인가요?

입문 자료에서는 비슷하게 묶어 말하기도 한다. 엄밀히 구분하면 ADT는 제공해야 할 행동과 규칙을 추상적으로 정의하고, 자료구조는 그 행동을 실제 데이터 배치로 구현하는 쪽에 가깝다. 중요한 것은 “무엇을 할 수 있는가”와 “내부에서 어떻게 만들었는가”를 구분하는 것이다.

### 배열은 왜 인덱스가 0부터 시작하나요?

배열의 시작 위치에서 얼마나 떨어져 있는지를 인덱스로 생각하면 자연스럽다. 첫 원소는 시작점에서 0칸, 두 번째는 1칸 떨어져 있다. 메모리와 주소 계산은 2일차와 4일차에 더 자세히 다룬다.
